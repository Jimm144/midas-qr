# Deep Research

## When to Use This Skill
- Investigating a complex technical question with no obvious answer
- Evaluating tradeoffs between multiple approaches
- Gathering evidence before making an architecture or tooling decision
- Synthesizing information from multiple sources into a structured recommendation

## Workflow
1. Define the research question clearly — what decision depends on the answer
2. Identify sources: official docs, GitHub issues, blog posts, benchmarks, and community discussions
3. Gather evidence: read, take notes, and bookmark primary sources
4. Cross-reference: compare claims across independent sources
5. Identify gaps: what's missing from the available evidence
6. Evaluate tradeoffs: weigh pros, cons, and context for each option
7. Structure the output: question, evidence, analysis, recommendation
8. Cite sources so the reasoning can be verified

## Rules
- Always cite primary sources — don't repeat unverified claims
- Distinguish between facts, opinions, and speculation
- Present multiple perspectives before making a recommendation
- Acknowledge uncertainty — don't overstate confidence in conclusions
- Revisit conclusions when new evidence emerges
- Keep the research focused on the original question
